Method: three parallel deep sweeps (security/auth, engine correctness, frontend
health) plus direct measurement of the repo, the deploy gap, and the running
app. Every critical claim below was re-verified by hand before being written
down. File:line references are current as of `70bd7a6`.

## 0. ACT NOW — one finding outranks everything else

**The production Neon connection string — password included — is committed to
a PUBLIC GitHub repo.** It sits in `.claude/settings.local.json` (inside a
permission-allowlist entry), tracked since commit `512e68f`, present in
`origin/main`. The repo `charliecro-blip/observatory` is public. Anyone who
finds it has **read-write access to the entire production database**: every
tester's natal data, journals, tasks, and advisor conversations.

What is already done (this session, `70bd7a6`): the file is untracked and
gitignored, so the tip of `feat/tides-app` no longer carries it. That is
containment, not a fix — the string remains in git history and in `main`.

**What only you can do, today:**
1. Neon console → the database's **Reset password**. This invalidates the
   leaked string everywhere at once.
2. Update `DATABASE_URL` on Railway (and your local `.env`) with the new
   string. Deploy restarts pick it up.
3. Optional, after rotation: history scrubbing (BFG / `git filter-repo`) or
   simply accept that a **dead** credential is in history. Rotation is what
   makes it dead; scrubbing without rotation is theatre.
4. Check the Neon dashboard's connection/activity logs for unfamiliar access
   since late July, if available on your plan.

Until rotation happens, treat the database as exposed.

## 2. Security (beyond §0)

**Live, fixed this session:**
- `routes/ical.ts` accepted the tester id from `?tid=` — the exact
  credential-in-URL pattern the 2026-07-30 feed-token withdrawal closed. The
  withdrawal fixed `exportIcal.ts`; this older sibling stayed mounted through
  the `routes/index.ts` barrel while nothing in the client linked to it.
  Deleted (`70bd7a6`). Settings' broken "Download .ics" button (still built
  `?testerId=` URLs the server ignores) fixed in the same commit.

**Open, worth a sprint item each:**
- **Rate limiting keys on `x-tester-id`** (`app.ts:59,78,89`) — an
  attacker-chosen header. Rotating it per request bypasses the general
  limiter, the AI limiter, and the 5/hr account-deletion cap. Only
  `recoverLimiter` is IP-keyed. The deletion cap in particular exists to stop
  bulk wipes from leaked ids and is currently decorative.
- **Uncapped AI path**: `GET /api/body-weather/today` (`bodyWeather.ts:377`)
  calls OpenAI on cache miss, and `POST /api/check-ins` invalidates that
  cache — alternating the two drives inference at the general 1000/15min
  limit instead of the AI cap.
- **`GET /api/studio/cycle.png?tester=`** (`studio.ts:249`) — renders an
  account's wins/momentum from a query-param id; the link is emitted into the
  DOM (`Momentum.tsx:189`), so it lands in history and referrers. Same
  pattern family as ical; smaller blast radius.
- **No security headers in production.** They live in `vercel.json` — and
  Vercel is retired. Express serves with no helmet, no `X-Frame-Options`,
  no `Referrer-Policy` (which compounds the cycle.png link above). One
  `helmet()` line closes this.
- **`POST /api/events`** accepts any tester id unauthenticated — telemetry
  and the error dashboard are attacker-poisonable. Known trade-off; note it.
- Recovery codes are ~40 bits with per-IP limiting only — fine for beta,
  undersized for "real accounts." Engine-token compare is non-constant-time
  (`engine.ts:38`) while `events.ts:37` does it right — make them match.

**Verified clean:** every per-tester route checks the header; `/engine/*` is
fully covered by `engineAuth` and fails closed; logs redact correctly and
query strings never reach them (which is what keeps feed tokens out); account
deletion's schema-derived table list holds; no other secrets in the repo.

## 3. Engine correctness

The timing-accuracy audit of 07-31 fixed the printed-clock class. What remains
is mostly the *fabrication* class — the exact thing the house rules ban:

- **`electionEngine.ts` never reads `polar`** — zero occurrences. At a known
  polar-latitude location it builds hour candidates on the fabricated
  12-hour day `astro.ts:485` invents, and counts them as the
  `planetary-time` family. Every sibling (dayTimeline, longSession,
  synthesis) checks; the canonical authority is the one that doesn't. Same
  gap in `timingTier.ts:148`, `inceptionElection.ts:439,502`,
  `studioCard.ts:138`, `dayarc.ts:398`, `routes/habits.ts:111`.
- **`astro.ts:874`** — `hoursAgo: orb / 0.5` assumes a constant lunar speed
  the codebase itself documents as varying ±25% (`dayTimeline.ts:132`), and
  it is printed to users via `inceptionElection.ts:324` ("3.4h ago").
- **`notifier.ts:260`** — a subscriber with no stored coordinates is emailed
  a day computed for New York (lat/lon default `40.7/-74.0`), with no
  `locationKnown: false` anywhere in the notifier path. ~20 route handlers
  share the same silent NYC default for omitted `lat`/`lon`.
- **`weekWeaver.ts:209`** charges 45 invented minutes of day-load for items
  the day weaver will later *refuse* to place — phantom occupancy that
  steers real items toward the wrong days. The code even warns about this
  population three lines later, then bills for it anyway.
- **Day boundaries use server-local time in the weavers.**
  `dayWeaver.ts:157-159`, `weekWeaver.ts:86,117-118`, `dayTimeline.ts:123`,
  `longSession.ts:145` all use local `Date` getters; prod is UTC, so for an
  Austin user after ~7 PM, "today" is already tomorrow — in the module that
  decides what is overdue. `WeaveOpts` has no `tzOffsetMin` field, so no
  caller can currently fix it. This is the same disease as the
  server-formats-in-its-own-timezone bug, in date arithmetic instead of
  formatting.
- **Four parallel graders besides the canonical engine**: `inceptionElection`
  (own verdict scale), `studioCard` (own ACTIVITIES table, re-implemented
  scoring with *different constants* — 1.15 vs 1.1 — and the dependency runs
  backwards: electionEngine imports from studioCard), `timingTier` (grades
  from the energy curve), `synthesis` (own dignity weighting the engine
  never consults). `tests/oneAuthority.test.ts` guards none of these four.
  The same moment can be "great" in one voice and "defer" in another.
- Smaller: `dignity.ts:193` defaults sect to day when unknown (latent);
  `timingTier` maps an empty/flat curve to "workable"; Placidus clamps
  silently above ~66°N (`houses.ts:91,105`) instead of refusing.

**Untested load-bearing modules** (no test file at all): `dignity`, `houses`,
`ephemeris`, `inceptionElection` (543 lines, a public verdict surface),
`studioCard` (884 lines, engine dependency), `timingTier`, `notifier`.
17 of 42 lib modules in total.

## 4. Frontend health

- **~1,500 truly dead lines**: `Currents.tsx` (433), `TideCard.tsx` (286),
  `CurrentsContextHeader.tsx` (142), `Orrery.tsx`, `FourTides.tsx`, plus the
  default export of `Sky.tsx` (~450 of its 719 lines unreachable — only two
  named exports are used). Expect the source-text-test trap on deletion:
  tests that regex raw source will pin some of these.
- **Planets page hangs by a thread**: reachable only via a planet chip inside
  the Log sub-tab (`App.tsx:1113` → `Log.tsx:490`). One refactor away from
  orphaned. If demotion is the intent, say so in a comment on the view
  switch.
- **Error handling is one page deep.** The three-state `listState` pattern
  (`Tasks.tsx:256`) and Home's outage handling exist and are correct — and
  are used nowhere else. `Planets`, `Habits`, `GuidingStarsHub` have *zero*
  error branches on read queries: a failed stars fetch renders "Set your
  first Guiding Star" to a user who has stars. Today.tsx has sixteen
  unguarded reads. (The `networkMode: "always"` change this session makes
  these failures *reachable*; the pages must now say something honest when
  they fire.)
- **Two alpha-suffix-on-var bugs** (the documented trap, recurring):
  `Log.tsx:279` live (selected range pill has no background),
  `Today.tsx:2463` latent (non-standard hour ruler → borderless card).
- **189 hardcoded hex colors** remain in pages/components that ignore
  `data-theme` — the likely substrate of the known 15 marginal dark-mode
  failures. Led by Today.tsx (44), GuidingStarsHub (29), Settings (26).
- **Accessibility is the weakest area of the codebase**: 9 aria-labels in
  27.6k lines; 24 icon-only buttons with no accessible name (including every
  delete button); 19 unlabeled inputs and 22 unlabeled selects; zero
  `htmlFor`/`id` pairs. One systemic fix covers most of Settings: its
  `Field`/`SettingsInput` pair (`Settings.tsx:843`) renders labels as
  siblings with no association.
- **Maintainability**: 7 files ≥ 1,000 lines hold 44% of the frontend;
  `Today.tsx` alone is 3,559 lines (13%).
- Cosmetic-but-real: `ELEMENT_SURFACE = LIGHT` is an alias, not a copy
  (`elements.ts:53`) — mutation of either changes both, contradicting the
  comment above it.
